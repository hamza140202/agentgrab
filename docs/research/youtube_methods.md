**The central verified finding:** in late 2026 YouTube evaluates **IP reputation BEFORE the PO-token check**. From a flagged datacenter IP, the Innertube *player* request returns `LOGIN_REQUIRED / "Sign in to confirm you're not a bot"` regardless of player client (`tv`, `android_vr`, `ios`, `mweb`, `web_safari`, `android`, `web_embedded`, `tv_simply`, `tv_downgraded`, `visionos` — all tested) and regardless of a valid, freshly-minted player PO token (tested with bgutil). Every method that actually works from a datacenter IP works because **some other, cleaner IP touches YouTube** (frontend instance, cobalt backend, relay, proxy/tunnel). See §2 for the raw evidence.

## 1. Background: what YouTube enforces in 2026

- **PO (Proof-of-Origin) tokens** — attestation blobs generated by BotGuard (Web), DroidGuard (Android), iOSGuard (iOS). Bound either to the **visitor ID/session** or (increasingly, since ~mid-2025) to the **video ID**. Lifetime ≈ 6–12 h (yt-dlp webpo cache spec default TTL 21 600 s). [DOCUMENTED: yt-dlp wiki PO-Token-Guide, `pot/_builtin/webpo_cachespec.py`]
- **Three PO-token contexts:** `player` (Innertube `/player` request), `gvs` (googlevideo stream URLs), `subs` (subtitles). [DOCUMENTED: yt-dlp wiki + `_base.py` `_PoTokenContext`]
- **JS challenges (n/sig deciphering):** since yt-dlp 2025.11.12, YouTube extraction requires an **external JavaScript runtime** + the official **`yt-dlp-ejs`** challenge-solver package. Without it: "YouTube extraction without a JS runtime has been deprecated, and some formats may be missing." PhantomJS/JSInterp path removed for YouTube. [VERIFIED: warning reproduced in live run; DOCUMENTED: wiki/EJS.md]
- **Guest-session rate limits:** ~300 videos/hour (~1000 webpage/player requests/hour) for anonymous sessions; ~2000 videos/hour for accounts; exceeding → "This content isn't available, try again later". [DOCUMENTED: yt-dlp wiki/Extractors]
- **OAuth login is dead** for yt-dlp ("logging in with OAuth no longer works"). Cookies are the only account path — out of scope for AgentDL. [DOCUMENTED: wiki/Extractors]
- **SABR (YouTube's server-adaptive streaming):** `web` client only serves SABR formats now; some clients return SABR-only depending on version/experiments (e.g. android_vr clientVersion >1.65 → SABR-only). yt-dlp exposes no generic SABR download path; SABR-locked formats are effectively unusable. [DOCUMENTED: `_base.py` comments]
- HLS (m3u8) formats historically exempt from GVS PO tokens; but "Since 2026.07, HLS formats are only returned with some logged-in or 'trusted' sessions" (`web_safari` note). [DOCUMENTED: `_base.py`]

## 3. Method: yt-dlp player-client rotation (baseline; no PO tokens)

### 3.1 Available clients (yt-dlp 2026.08.19, `youtube:player_client=…`) [DOCUMENTED — README master]

`web`, `web_safari`, `web_embedded`, `web_music`, `web_creator`, `mweb`, `ios`, `visionos`, `android`, `android_vr`, `tv`, `tv_downgraded`, `tv_simply`.

- Default (logged out): **`visionos,web`**; `web` omitted if no JS runtime.
- Default (logged in): `web_embedded,tv_downgraded,web` (free) / `web_creator,tv_downgraded,web` (premium). `web_music` for music.youtube.com.
- `tv_downgraded`/`web_embedded` are added as fallback if `android_vr`/`visionos` fail.
- `default` / `all` keywords accepted; exclude with `-` prefix, e.g. `youtube:player_client=default,-web`.
- Client-name handling: `_split_innertube_client` also accepts dotted variants (`tv.foo`) for experimentation.

### 3.2 PO-token requirement per client (from yt-dlp wiki PO-Token-Guide + `_base.py` policies) [DOCUMENTED]

| Client | PO token required for | Notes (2026) |
|---|---|---|
| `web` | Subs, GVS | SABR-only formats; needs JS runtime |
| `web_safari` | GVS (HLS exempt**) | *Since 2026.07 HLS only with logged-in/"trusted" sessions |
| `mweb` | **GVS** | **the wiki's recommended client when combined with a PO token** |
| `tv` | Not required | All formats DRM'd if cookies aren't passed; SABR-only in some cases |
| `tv_simply` | GVS | account cookies not supported |
| `tv_downgraded` | Not required | new fallback client (TVHTML5 v5) |
| `web_embedded` | Not required | only embeddable videos |
| `web_music` | GVS | |
| `web_creator` | GVS | **requires auth** |
| `android` | GVS **or** Player | cookies not supported |
| `android_vr` | Not required (policy) | **⚠ 2026 reality: since 2026.07 selective POT enforcement for non-HLS; since 2026.08.17 all formats 403 at clientVersion 1.65.10; "Made for kids" unavailable** — no longer a reliable free lunch |
| `ios` | GVS or Player | cookies not supported; HLS live requires POT 30 s in |
| `visionos` | Not required (default policy) | new default primary client (clientName VISIONOS, 1.02) |

For all clients: GVS POT not required for Premium; HLS live streams don't need POT (except `ios`).

### 3.3 Exact extractor-args syntax (yt-dlp ≥ 2026.08) [DOCUMENTED]

```bash
yt-dlp --extractor-args "youtube:player_client=tv,mweb" \
       --extractor-args "youtube:formats=missing_pot" \
       "https://www.youtube.com/watch?v=VIDEO_ID"
```

Full YouTube arg list (relevant subset):
- `player_client`: as above. CLI also accepts `player-client` (hyphen).
- `player_skip`: `configs`, `webpage`, `js`, `initial_data` — fewer requests / less rate-limit exposure, riskier metadata.
- `formats`: `missing_pot` **includes formats that require a PO token but none was provided** (they will usually 403 at download time — last-resort salvage); `incomplete`, `duplicate`, `dashy` also exist.
- `po_token`: `CLIENT.CONTEXT+TOKEN` CSV, e.g. `youtube:po_token=mweb.gvs+XXX,mweb.player+YYY,web_safari.gvs+ZZZ` (contexts: `gvs`, `player`, `subs`). Case-sensitive clients; base64url token.
- `fetch_pot`: `never` | `auto` (default) | `always` — policy for querying installed PO-token *provider plugins* (`always` = fetch even if the client policy says not required).
- `visitor_data`: override Visitor Data for Innertube (use with `player_skip=webpage,configs`, no cookies). pairs with PO tokens bound to visitor ID.
- `data_sync_id`: account Data-Sync-ID override (account use-case only).
- `pot_trace=true`: debug logging for PO-token fetching. `jsc_trace=true` for JS-challenge logging.
- `use_ad_playback_context=true`: skip preroll ads/wait period (`mweb`/`web_music` only).
- `innertube_host`, `innertube_key`: API host/key overrides (e.g. `youtubei.googleapis.com`; host change verified live — does NOT change playability outcome).
- `lang`: metadata language.
- `youtube-ejs` extractor args: `jitless=true` for JIT-less JS runtime mode (safer, slower).

**Verdict for AgentDL:** client rotation alone is **necessary but insufficient** on datacenter IPs (VERIFIED: all 10 clients → LOGIN_REQUIRED). Still worth running as tier 1 because (a) mildly-flagged IPs and "whitelisted"/widely-cached videos sometimes pass (independent report: one very popular old video downloaded fine before the rest failed), and (b) failures are fast.

## 4. Method: bgutil-ytdlp-pot-provider (the yt-dlp PO-token ecosystem's flagship)

Repo: `github.com/Brainicism/bgutil-ytdlp-pot-provider` (v2.0.1, active — last commit 2026-10-02). Uses `LuanRT/BgUtils` to run BotGuard attestation **without a browser**. Featured on the yt-dlp PO-Token-Guide; maintained by a yt-dlp maintainer. [DOCUMENTED]

### 4.1 How it works
Two parts: (1) a **provider** that mints PO tokens — either an always-on **HTTP server** (port 4416, docker image with node or deno flavors) or a **script** (`generate_once.js`, spawned per yt-dlp call); (2) a **yt-dlp plugin** (PyPI `bgutil-ytdlp-pot-provider`) that hooks yt-dlp's built-in PO-Token Provider Framework, requests tokens via HTTP (preferred) or the script, and supplies them to the YouTube extractor. Tokens are cached (TTL via env `TOKEN_TTL`, default 6 h for script mode). **No cookies, no login required** — it mints *guest-session* WebPO tokens. [DOCUMENTED + VERIFIED: server + plugin ran end-to-end here]

### 4.2 Exact install steps (VERIFIED in this sandbox)

```bash
# 1) plugin (into same python env as yt-dlp)
python3 -m pip install -U bgutil-ytdlp-pot-provider

# 2) server (option a, HTTP — recommended)
git clone --single-branch --branch 2.0.1 https://github.com/Brainicism/bgutil-ytdlp-pot-provider.git
cd bgutil-ytdlp-pot-provider/server
npm ci && npx tsc          # node >= 22 (deno >= 2.0.0 alternative: deno install --allow-scripts=npm:canvas --frozen)
node build/main.js         # binds 127.0.0.1:4416 by default; flags: -p/--port, -H/--host (repeatable)
```

Docker alternative:
```bash
docker run --name bgutil-provider -d --init -p 127.0.0.1:4416:4416 brainicism/bgutil-ytdlp-pot-provider
# flavors: :latest / :node (node), :2.0.1-deno / :deno (deno)
```

Script mode (option b): keep the clone at `~/bgutil-ytdlp-pot-provider` (default lookup path) or pass
`--extractor-args "youtubepot-bgutilscript:server_home=/path/to/repo/server"`. Not recommended for high concurrency (process spawn per call, weak cache concurrency).

### 4.3 yt-dlp usage

Default URL (`http://127.0.0.1:4416`) needs zero flags:

```bash
yt-dlp --js-runtimes node --extractor-args "youtube:player_client=mweb,tv,web_safari" URL
```

Custom server URL: `--extractor-args "youtubepot-bgutilhttp:base_url=http://10.0.0.5:4416"` (multiple args for one provider are `;`-separated).

Verification lines (VERIFIED output):
```
[debug] [youtube] [pot] PO Token Providers: bgutil:http-2.0.1 (external), bgutil:script-node-2.0.1 (external, unavailable), ...
[youtube] [pot:bgutil:http] Generating a player PO Token for mweb client via bgutil HTTP server
```

### 4.4 Server HTTP API (VERIFIED against running v2.0.1; source `server/src/main.ts`)
- `GET  /ping` → `{"server_uptime":3.0,"version":"2.0.1"}`
- `POST /get_pot` → mints token (body: `{content_binding, remote_host(...)} `; used internally by the plugin)
- `POST /invalidate_caches`, `POST /invalidate_it`, `GET /minter_cache`, `GET /`
- CORS guard rejects cross-site browser origins (it's meant for localhost/agent use).

### 4.5 Datacenter-IP reality check [VERIFIED — the key caveat]
- Tokens **are** minted successfully from the datacenter IP (BotGuard attestation passes; `fetch_pot=always` produced "Retrieved a player PO Token for mweb client").
- The player request **still** returned `LOGIN_REQUIRED` afterward. Upstream README itself warns: *"Providing a PO token does not guarantee bypassing 403 errors or bot checks"* and *"a PO Token does not bypass IP-based login restrictions. If you still get 'Sign in to confirm you're not a bot' after a token was generated (common on datacenter IPs), you additionally need to pass cookies; see #37."*
- Therefore: bgutil fixes **GVS 403s** and helps on *mildly* flagged IPs; it does **not** defeat the playability gate on hard-flagged datacenter IPs. Keep it installed (cheap, ~15 s bootstrap) but do not treat it as a guaranteed bypass.

## 6. Method: yt-dlp-ejs / External JS (JSC) — what it is and why it matters now

[DOCUMENTED: wiki/EJS.md + PyPI + live run]

- Since **yt-dlp 2025.11.12**, YouTube downloads require solving YouTube's JS challenges (n/sig) with an **external JavaScript runtime**, using solver scripts from **`yt-dlp/ejs`**, shipped as PyPI package **`yt-dlp-ejs`** (v0.8.0; Unlicense; deps `meriyah` ISC + `astring` MIT).
- Runtimes: **deno ≥ 2.3 (recommended, enabled by default)**, **node ≥ 22** (`--js-runtimes node`), **quickjs/quickjs-ng** (`--js-runtimes quickjs`), **bun ≤ 1.3.14 (deprecated)**.
- Install options: `pip install -U "yt-dlp[default]"` (includes `yt-dlp-ejs`); official PyInstaller binaries bundle it; or on-the-fly script downloads via `--remote-components ejs:npm` (deno/bun) or `ejs:github`.
- EJS **replaces** the old in-process JS interpreter + PhantomJS for YouTube. Without it: warning + missing formats (VERIFIED: "No supported JavaScript runtime could be found…" then JS-less client flow).
- Related plugin: `grqz/yt-dlp-apple-webkit-jsi` (Apple WebKit JSC provider; Apple devices only).
- **Why it matters for AgentDL:** it's a hard dependency of any yt-dlp-based tier on a slim cloud image — install deno or node or the wheel, or extraction silently degrades. (In this sandbox: pip wheel present + node 24 → worked.)

## 7. Method: Invidious

### 7.1 Public instances — status Oct 2026 [VERIFIED live + DOCUMENTED]
- Official list (`api.invidious.io/instances.json?sort_by=health`) currently contains only **5 usable HTTPS instances**: `inv.nadeko.net` (CL), `yt.chocolatemoo53.com` (US), `invidious.tiekoetter.com` (DE), `invidious.nerdvpn.de` (CA), `invidious.f5.si` (JP) (+Tor/I2P/Yggdrasil mirrors). The docs blame "the recent YouTube issues" (iv-org/invidious#4734) for the shrunken list.
- **All of them deploy mandatory anti-bot systems** (list rule 14 — required!) e.g. Go-away CAPTCHA on nadeko, and rule 15 obliges operators to **rotate YouTube-facing IPs via proxies**. From our datacenter IP: `inv.nadeko.net` API → "Endpoint disabled"; `yewtu.be` → 403 (openresty); every other candidate → 403/502/dead. `api` flag is `false` for most list entries (public API off).
- **Conclusion: public Invidious instances are NOT a viable programmatic source for an agent** (they exist for humans in browsers).

### 7.2 API shape (still useful for self-host / when reachable)
- `GET /api/v1/videos/{id}` → JSON with `title`, `formatStreams[]` (muxed: itag 18 360p etc.), `adaptiveFormats[]` (video-only + audio-only), `captions[]`, `recommendedVideos[]`, `error` on failure.
- Direct stream URL: `GET /latest_version?id={id}&itag={itag}&local=true` → 302 to googlevideo (with `local=true` the **instance proxies** the bytes through its own IP — the classic datacenter-IP bypass; most instances disabled it due to bandwidth).
- DASH: `GET /api/manifest/dash/id/{id}` (+`?local=true`).
- Rate limits: instance-defined; commonly Anubis/Go-away + IP throttling (no standard).

### 7.3 Invidious companion [DOCUMENTED]
- `iv-org/invidious-companion` (Deno; active, last commit 2026-09-19). Successor to `inv-sig-helper`: **handles ALL YouTube stream retrieval** (decryption of videoplayback URLs, POT/session handling) using a maintained iv-org YouTube.js fork.
- Default `127.0.0.1:8282`, bearer auth (`Authorization: Bearer SECRET`, must equal Invidious `invidious_companion_key`), config via `config/config.example.toml`.
- Standalone HTTP API (usable **without** Invidious!):
  - `POST /companion/youtubei/v1/player` body `{"videoId":"..."}` → YouTube player response with **decrypted, ready-to-use videoplayback URLs** (client type not selectable via API).
  - `GET /companion/api/manifest/dash/id/{id}` (DASH manifest, decrypted URLs; `?local=true` to proxy).
  - `GET /companion/latest_version?id={id}&itag=18&local=true`.
- Wiki guides cover systemd, separate subdomain, per-request IPv6 rotation ("How to send IPv6 requests with a new IPv6 address for each request on a server with a whole IPv6 range" — the current meta-trick for self-hosters), and hardcoded `player_id`.
- **AgentDL fit:** self-hosting Invidious+companion on a **clean-IP** VPS (or with a rotating IPv6 block / proxies) is a legitimate cookieless pipeline; on a datacenter IP it inherits the same playability wall (companion fetches from *your* IP by default).

## 9. Method: Cobalt API

[DOCUMENTED from `imputnet/cobalt` docs; repo last commit 2026-04-06 — development notably quiet in H2 2026]

### 9.1 How the API works
- `POST /` with `Accept: application/json`, `Content-Type: application/json`:
  ```json
  {"url":"https://youtu.be/jNQXAC9IVRw",
   "videoQuality":"1080","youtubeVideoCodec":"h264","youtubeVideoContainer":"auto",
   "downloadMode":"auto","audioFormat":"mp3","audioBitrate":"128",
   "filenameStyle":"basic","alwaysProxy":false,"localProcessing":"disabled",
   "youtubeBetterAudio":false,"youtubeHLS":false,"subtitleLang":"en"}
  ```
- Response `status` ∈ `tunnel | redirect | picker | local-processing | error`:
  - `tunnel`: `{"status":"tunnel","url":"https://<instance>/tunnel?…","filename":"…"}` — download via that URL (cobalt **proxies/remuxes** the stream itself; your IP never touches googlevideo).
  - `local-processing`: tunnels + remux instructions (you merge locally with ffmpeg).
  - `error`: `{"status":"error","error":{"code":"…","context":{…}}}`.
- `GET /` → instance info (`cobalt.version`, `turnstileSitekey`, `services[]`). `GET /tunnel` serves the file; errors via HTTP codes (401/403/404/429/500).
- Rate limiting: standard `RateLimit-*` headers on all endpoints except `GET /`.

### 9.2 Auth
- Optional per-instance: **API keys** (`Authorization: Api-Key UUID`) and/or **Cloudflare Turnstile → JWT** (`POST /session` with `cf-turnstile-response` header → `Authorization: Bearer JWT`, short-lived). Missing auth → `error.code = api.auth.<method>.missing`.
- Official hosted `api.cobalt.tools` uses bot protection and explicitly forbids programmatic use. **Self-host or get permission.**

### 9.3 Public instance lists
- Community list at **`instances.cobalt.best`** — VERIFIED problematatic right now: host resolves (172.241.213.98) but serves an **invalid TLS cert** (ERR_CERT_AUTHORITY_INVALID) behind an anti-bot JS challenge (Anubis-style JToken) + 429s — effectively unusable for automated discovery. Treat any third-party list as untrusted; prefer your own self-hosted instance or direct arrangement with instance owners. [Historical alternative: uosc's `instances.cobalt.best` JSON — UNVERIFIED]
- The official project publishes **no** public API instance list anymore ("there is currently no publicly available pre-hosted api").

### 9.4 Self-hosting (recommended cobalt path for AgentDL)
- Docker compose: `docker compose up -d` (image auto-updates via watchtower); only `API_URL` required; cookies.json optional for private content.
- YouTube-specific env (from `docs/api-env-variables.md`):
  - `YOUTUBE_SESSION_SERVER` → URL of an **`imputnet/yt-session-generator`** instance (auto-pulls `po_token` + `visitor_data`; docker: `docker run -p 8080:8080 ghcr.io/imputnet/yt-session-generator:webserver`).
  - `YOUTUBE_SESSION_INNERTUBE_CLIENT` (default `WEB_EMBEDDED`), `YOUTUBE_PLAYER_ID` (player ID list), `ENABLE_DEPRECATED_YOUTUBE_HLS=key`, `YOUTUBE_ALLOW_BETTER_AUDIO=1`.
  - Abuse protection: `JWT_SECRET`, Turnstile keys, `RATELIMIT_WINDOW/MAX` (default 60 s), `SESSION_RATELIMIT_*` (60 s / 10).
- **Cobalt self-hosted on a clean IP is one of the best cookieless designs** (its own backend does the YouTube session; your agent just POSTs URLs). Rate limit it yourself; remember cobalt tunnels all bytes (bandwidth cost).

## 10. Method: YouTube.js (`LuanRT/YouTube.js`, npm `youtubei.js`)

[DOCUMENTED from README; VERIFIED live test on datacenter IP]

- JS client for Innertube; runs on Node ≥ 22-ish, Deno, browsers. `npm install youtubei.js@latest`. Active (last commit 2026-09-24). Docs: **ytjs.dev**.
- Usage: `const yt = await Innertube.create({client_type:'WEB'}); const info = await yt.getInfo(id);`
- Live test: WEB → `LOGIN_REQUIRED "Sign in to confirm you're not a bot"` (0 formats); ANDROID/TVHTML5/MWEB → null-parser errors (playability gate again); IOS → request failure. **Not a bypass by itself on datacenter IPs.**
- Where it *is* relevant: it's the engine under Invidious-companion (iv-org fork) and pairs with **`LuanRT/BgUtils`** (BotGuard library: fetches attestation challenges via Innertube `getAttestationChallenge('ENGAGEMENT_TYPE_UNBOUND')` or `jnn-pa.googleapis.com/$rpc/google.internal.waa.v1.Waa/Create`, runs the interpreter VM in a JS runtime, mints WebPO tokens bound to visitor ID or video ID) — i.e. the DIY path to build your own POT provider inside a Node service. Also `YoutubeDL` helpers exist in the library for direct download. It cannot bypass BotGuard ("you still need a runtime environment that meets its checks") nor the IP-reputation playability gate.

## 11. Method: raw Innertube (`youtubei/v1/player`) without login

[VERIFIED dead on datacenter IP]
- Endpoint patterns (legacy but still served): `POST https://www.youtube.com/youtubei/v1/player?key=<WEB/ANDROID key>` or keyless `POST https://youtubei.googleapis.com/youtubei/v1/player` with `Content-Type: application/json` and client-appropriate `User-Agent`.
- Minimal ANDROID context (VERIFIED payload):
  ```json
  {"context":{"client":{"clientName":"ANDROID","clientVersion":"21.26.364","androidSdkVersion":30,"hl":"en"}},"videoId":"jNQXAC9IVRw"}
  ```
  → `playabilityStatus.status = LOGIN_REQUIRED`, reason "Sign in to confirm you're not a bot", no `streamingData`. Same on `youtubei.googleapis.com` with IOS context.

- Note: even on success, n-decipher of throttled URLs needs the player JS (today: via `yt-dlp-ejs` or YouTube.js solver).

## 12. Method class: route the request through a cleaner IP (the 2026 meta)

Since the block is at IP reputation, all surviving cookieless approaches either (a) have a *cleaner-IP service* do the YouTube touch (cobalt backend, Invidious/companion instance with `local=true`, community relays), or (b) move *your* egress IP. Options, with field experience from the ytagent write-up [DOCUMENTED, cross-checked against our findings]:

1. **Cloudflare WARP** (warp-cli or docker `caomingjun/warp`): egress via Cloudflare IPs → usually passes the playability gate; free; adds latency; occasionally WARP ranges get flagged too. Combined with bgutil POT this is the strongest *self-contained* stack: WARP egress + node + deno + yt-dlp + bgutil.
2. **Paid residential/ISP proxies** (`--proxy socks5://user:pass@host:port` or `--source-address`): most reliable in practice; costs money; ToS/compliance considerations. Rotating: re-check per video (two-phase proxy test: watch page → player API `streamingData` presence).
3. **Free SOCKS5 lists**: works (0.5–2 % pass rate after two-phase testing; 1–5 MB/s) but fragile/ephemeral — acceptable only as a last-resort tier.
4. **GitHub Actions farm** (Azure IPs, different reputation) + WARP inside the runner; download artifact via API. Limits: 6 h job, 10 GB artifact, ~15 dispatches/min, 100 artifact downloads/h. Fully cookieless; awkward latency (minutes).
5. **Cloudflare Workers / other PaaS edge** (residential-like reputation): proxy the innertube calls through a Worker; UNVERIFIED at scale, likely ToS-sensitive.
6. **Whole IPv6 block rotation** on a VPS with a /64: companion wiki documents per-request IPv6 source rotation — cheap and effective if your provider gives a clean block (UNVERIFIED general case; YouTube heavily scrutinizes /48 datacenter blocks).

## 14. Recommended fallback chain for AgentDL (derived from findings)

0. **Preflight:** resolve video ID; (optional) transcript/OEmbed reachability probe.
1. **yt-dlp default** (`visionos,web`) + node/deno runtime + `yt-dlp-ejs` — fast fail on flagged IPs.
2. **yt-dlp + bgutil server** (`mweb,tv,web_safari; fetch_pot=auto`) — catches mildly-flagged IPs and GVS-403 cases.
3. **Cobalt**: self-hosted instance if provisioned; else configured community instance(s) (respect their auth/rate limits).
4. **Invidious/companion** self-host or a vetted instance with `local=true` / `/companion/latest_version`.
5. **Egress change:** WARP docker sidecar → retry tiers 1–2 through it (`--proxy`).
6. **Paid residential proxy** (`--proxy socks5h://…`) retry.
7. **Last resort:** free SOCKS5 two-phase farm, or GitHub-Actions download farm + artifact pull.
8. **Verifier** on every artifact (size ≥1 MB, magic bytes, ffprobe duration, moov atom) + a Truth/learning layer that reorders tiers from observed success (pattern proven in the ytagent design; failures across tiers are independent).
